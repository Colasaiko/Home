为什么要了解这个问题？

核心的配置格式与图形应用的订阅导入功能不能混为一谈，改后缀不会完成转换。

导入失败往往是配置格式和客户端不匹配，而非服务商所有节点都坏了。按获取、导入、激活、验证四个环节操作，可以发现配置尚未启用或系统流量没有进入客户端的问题。

直接回答

sing-box 通常使用 JSON 运行配置；若使用带订阅管理的图形客户端，先核对它接受什么订阅格式再导入。

如何处理这个问题？

按下面的顺序操作，每完成一步再进入下一步；已经确认的条件可以直接通过目录跳到对应环节。

步骤 1：确认使用核心还是图形客户端

先区分自己直接运行 sing-box 核心，还是在手机或电脑上使用带订阅功能的图形应用。核心读取 JSON 配置；图形客户端能导入哪些订阅，应以该应用的说明为准。

步骤 2：获取与当前版本匹配的 JSON

优先使用本人后台明确提供的 sing-box 配置，或由自己控制的工具转换。核对配置版本、出站协议、DNS 和路由，不把 Clash YAML 改成 .json 就当成转换完成。

选好客户端后，再核对品牌提供的配置。例如 Firefly 的资料涉及 VLESS，可用来检查客户端的协议支持；无忧 的介绍提到自研客户端，可继续查看安装入口与系统要求。以实际拿到的订阅格式为准。

步骤 3：检查配置并启用所需入口

直接使用核心时，可按官方文档运行 sing-box check -c config.json 检查配置。图形应用则选择并激活配置，确认 VPN 或系统代理权限；先保留原有可用配置再切换。

步骤 4：验证请求路径和更新方式

启动后用真实网页检查连接与规则，再确认后续由哪个应用或流程负责更新节点。解析错误按文档核对字段，连接错误检查日志；不要用不明在线转换器处理私人链接。

完成后怎么判断？

sing-box 可以更新节点列表，当前配置已激活，目标请求在连接日志中走到预期节点。

容易忽略的地方

sing-box 通常使用 JSON 配置；兼容客户端提供的订阅功能不等于核心能直接解析任何订阅 URL。

官方资料与进一步核对

客户端菜单与平台条件可能变化，操作前核对对应开发者或平台说明。
