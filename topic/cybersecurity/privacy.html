机场隐私与防泄漏：从订阅保管到实际验证

购买套餐只解决访问服务的条件。订阅凭据、客户端接管范围、域名解析和浏览器通信仍需要分别检查。这里帮助你判断信息流向谁，以及一个测试结果能说明什么。

信息流向 · 六步检查 · 结果与记录

为什么连接成功以后，还要检查隐私？

代理出口改变，不代表设备完全匿名。HTTPS 保护的是客户端与目标服务之间的加密通信；服务提供者仍可能接触连接元数据，目标平台仍有账号、会话和风控规则。线路标注、价格与宣传中的“无日志”也不能由本页工具独立验证。

工具入口是 配置检查与隐私测试 和 IP / Base64 工具箱。先了解数据流向，再决定是否提交内容。

如何按顺序检查？

  1. 确认客户端来源与配置格式。核对开发者渠道、系统版本和服务提供的订阅类型。遇到导入问题，先看 客户端选择，再做本地格式检查。
  2. 保管订阅凭据。不公开订阅 URL、token、节点密码或带凭据的二维码。泄漏以后使用服务后台提供的重置方式，并更新自己的设备。转换服务会接触原订阅，不把陌生转换站当作默认必需步骤。
  3. 确认应用走哪条路。系统代理、规则模式和 TUN 的覆盖范围不同。分别验证浏览器和实际应用，结合日志看命中的规则；不要只凭“开启 TUN”判断全部通信已接管。
  4. 核对 DNS。记录客户端 DNS 配置、浏览器安全 DNS 设置及测试返回的解析器。DoH 加密解析请求，不等于所有流量都经过代理；无法解析时按照 DNS 故障步骤处理。
  5. 解释 WebRTC 结果。区分私有地址、代理出口和自己已知的公网地址。浏览器权限与网络条件会影响候选收集；没有结果只能说明这次没有收集到证据。
  6. 回到实际任务复测。对照同设备、同时间、同目标的结果，确认修改后的行为。遇到请求失败，继续看 网络与节点故障判断，不要用“泄漏”概括所有错误。

1客户端和订阅能否匹配？先核对来源、版本与格式

怎么检查：在客户端的“关于”页面记录版本，核对下载来源，再到品牌后台查看它提供的订阅格式。导入失败时，记录具体错误提示。

看什么结果：客户端支持所选格式，能正常读取节点。导入成功只说明配置可以读取，还需要继续验证连接。

有问题时：先核对客户端与格式；使用配置检查工具时，先阅读其数据处理说明。

2订阅凭据有没有被公开？检查截图、分享链接与转换服务

怎么检查：回看自己分享过的截图、二维码和链接，确认是否包含完整订阅地址、token 或节点密码；核对曾经使用过的订阅转换服务。

看什么结果：公开内容中没有可用凭据。第三方转换服务会接触原订阅，不能只凭“转换成功”判断凭据得到妥善保管。

有问题时：进入品牌后台，使用它提供的订阅重置方式，再更新各设备上的订阅；没有重置入口时向服务方确认处理方法。

3实际应用的出口和 DNS 对得上吗？分别检查浏览器与正在使用的应用

怎么检查：记录当前规则模式、系统代理或 TUN 设置，查看应用请求命中的规则；查询浏览器出口 IP，并记录客户端 DNS、浏览器安全 DNS 设置与测试返回的解析器。

看什么结果：实际请求走的路径符合你设置的规则。浏览器的 IP 结果只能说明该次浏览器请求的出口，不能代替其他应用的验证；解析器名称不同也不能单独认定泄漏。

有问题时：连接失败先看具体日志；DNS 解析失败按 DNS 排查文章逐项对照，每次修改后回到原应用复测。

4测试结果能解释、能复现吗？对照修改前后，留下脱敏记录

怎么检查：记录测试时间、设备、客户端版本、目标、错误提示和修改项，在同一设备与目标上重新测试。WebRTC 结果需要区分私有地址、代理出口和自己已知的公网地址。

看什么结果：能说明哪项设置改变了哪次请求的表现。WebRTC 没有收集到地址，也不能据此证明所有通信都没有泄漏。

有问题时：把失败定位到 DNS、客户端、节点或目标服务，再选择对应的处理方法。分享记录前遮住订阅、密码和个人地址。
